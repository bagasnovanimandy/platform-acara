## Keputusan
<!-- keputusan baru yang tidak ada di HANDOVER, beserta alasannya -->
- Generator Prisma memakai `prisma-client` (bukan `prisma-client-js` yang deprecated di Prisma 7), output `src/generated/prisma`, format CJS, karena NestJS dikompilasi ke CommonJS.
- `/health` mengembalikan 503 `{code: "DB_DOWN"}` bila database mati, supaya healthcheck Docker/Traefik nanti bermakna.
- Test memakai Vitest di semua paket (lebih ringan dari Jest).
- `packages/shared` dan `packages/face` di-build ke `dist/` (CJS) agar bisa dipakai NestJS; Next.js memakai `transpilePackages`.
- Nama queue BullMQ per consumer: `core-events`, `acara-events`, `wabot-events` (`QUEUES` dan `EVENT_ROUTES` di events.ts).
- Prettier tidak memformat `*.md` dan `infra/` agar dokumen asli tidak berubah.
- Hak akses: SUPER_ADMIN semua; ADMIN mengubah data di scope-nya; PENGURUS hanya melihat (mengambil keputusan izin di fase 7). Membuat daerah hanya SUPER_ADMIN; desa butuh scope daerah; kelompok butuh scope desa.
- Scope dihitung per request dari tabel UserScope + pohon wilayah (`computeScope`, fungsi murni). Scope DESA/KELOMPOK tetap melihat nama induknya agar pilihan bertingkat utuh. Data di luar scope dibalas 404 (detail) atau 403 `OUT_OF_SCOPE` (membuat data).
- Kode anggota `<kodeDesa>-<urut 4 digit>` memakai tabel baru `KodeCounter` (increment atomik). Kode tidak berubah saat mutasi.
- Mutasi: anggota harus di scope asal; kelompok tujuan boleh di luar scope (pindah keluar). UI hanya menampilkan kelompok yang terlihat oleh user.
- Refresh token stateless (JWT `typ: refresh`), dikirim sebagai cookie httpOnly `refresh_token` (juga di body untuk klien non-browser). User nonaktif ditolak saat refresh. Belum ada pencabutan token per sesi.
- Kunci JWT: `JWT_PRIVATE_KEY` (PEM) atau file `keys/jwt-private.pem`; di dev dibuat otomatis, di produksi wajib.
- Web memanggil core lewat rewrite `/api/core/*` (satu origin, cookie aman). Access token hanya di memori (zustand); saat halaman dibuka ulang, web memanggil /auth/refresh.
- Payload `anggota.upserted` ditambah `namaKelompok`, `namaDesa`, `namaDaerah` agar `AnggotaRef` di acara-svc terisi tanpa memanggil core.
- Event dikirim setelah commit dengan `addBulk` dan batas waktu 3 dtk per queue. Bila Redis mati, request tetap berhasil dan event dikirim saat Redis kembali (offline queue ioredis); bila service mati sebelum itu, consumer resync via `GET /internal/anggota`.
- BullMQ 6 memerlukan `ioredis` sebagai dependensi langsung.
- Import: baris valid disimpan dalam satu transaksi, baris bermasalah dilewati dan dilaporkan (nomor baris Excel). No WA ortu → Wali (upsert per nomor) dengan hubungan WALI. Maks 5.000 baris / 5 MB.
- Kolom waktu core memakai `timestamptz` (`@db.Timestamptz(3)`), sesuai AGENTS.md.
- Kategori diisi manual per anggota dari hasil assessment (keputusan pemilik), tidak dihitung dari umur; satu anggota boleh banyak kategori (dipilih pemilik). Daftar kategori berlaku lintas wilayah dan hanya diubah SUPER_ADMIN atau admin daerah. `kode` kategori tetap walau nama diganti; payload `anggota.upserted.kategori` berisi daftar kode. Tanpa kategori = belum di-assessment.
- Fase 2 dipecah: tahap A (kategori, auditor, riwayat, admin bertingkat) dan tahap B (acara dengan tingkat kelompok/desa/daerah/gabungan + pilihan kategori, dashboard admin & auditor).
- Riwayat perubahan dicatat di core (`AuditLog`) dengan daerah/desa/kelompok. Auditor melihat entri yang wilayah paling spesifiknya ada di wilayahnya; entri tanpa wilayah (kategori) hanya untuk SUPER_ADMIN. Mutasi dicatat di wilayah asal dan tujuan.
- Admin bertingkat: ADMIN mengelola pengguna yang seluruh wilayahnya di dalam wilayah ADMIN itu (termasuk sesama admin di tingkat yang sama), dan hanya memberi wilayah di dalamnya.
- Komponen shadcn/ui ditulis manual (registry tidak bisa diakses dari lingkungan build); Select memakai `<select>` bawaan agar ringan di HP.
- Pesan validasi zod memakai locale Indonesia.
- Penyelenggara acara = wilayah terkecil yang mencakup semua wilayah peserta; hanya ADMIN di wilayah penyelenggara yang bisa mengubah. Acara terlihat bila penyelenggara atau salah satu wilayah peserta bersinggungan dengan wilayah user (auditor & pengurus hanya lihat).
- Acara gabungan lintas daerah belum didukung (ditolak `WILAYAH_INVALID`); gabungan boleh campur desa dan kelompok.
- Aturan peserta disimpan satu baris `PesertaRule` per wilayah dengan kategori & jenis kelamin yang sama; peserta dihitung saat dibaca dari `AnggotaRef` berstatus AKTIF (snapshot ke `PesertaSesi` saat sesi dibuka, fase 3).
- Item rundown dihapus permanen (bukan data inti); acara, sesi, dan foto memakai `deletedAt`.
- Foto dikecilkan di browser lalu dikonversi ulang di server dengan sharp; file di `UPLOAD_DIR/acara/<id>/`.
- Dashboard: agregasi dihitung di core per request (data per scope kecil, belum perlu tabel ringkasan). Kelengkapan dihitung atas anggota AKTIF; kontak dianggap terisi bila anggota punya No WA atau wali. Mutasi dibagi masuk/keluar/di dalam relatif terhadap scope pengguna; hari & bulan dikelompokkan dalam WIB.
- Grafik memakai recharts, gerak memakai `motion` (ringan, tanpa dependensi native). Gauge SVG sendiri (`role="meter"`). Warna seri dari palet dataviz (`--chart-*` di globals.css); batang kategori memakai warna kategorinya.
- Operator memakai JWT HS256 terpisah dari JWT pengguna (RS256 core) karena diterbitkan acara-svc dan dicabut lewat `OperatorSession.revokedAt`.
- Server menyimpan satu absensi per (sesi, anggota) dengan `capturedAt` paling awal; kiriman lain dicatat di `AbsensiDuplikat`. Kiriman ulang dengan `clientId` sama dibalas `SUDAH_DITERIMA`.
- Paket offline memuat embedding VERIFIED dan PENDING (wajah yang baru didaftarkan operator langsung bisa dipakai, ditinjau di fase 5).
- Backend tfjs dipilih eksplisit: WebGL, bila tidak ada CPU (file .wasm tidak ikut di-host).
- Service worker hanya aktif di build produksi; `/api` tidak pernah di-cache.
- Login PIN memakai **kode pintu** 6 karakter (tanpa huruf mirip) + PIN, karena PIN di-hash argon2 sehingga tidak bisa dicari langsung; kode juga tercetak di kartu.
- Reset PIN membuat QR baru juga, tetapi tidak mengeluarkan perangkat yang sudah masuk. Cabut mengeluarkan perangkat (kode `OPERATOR_DICABUT`) dan permanen.
- SSE monitor dibaca web lewat `fetch` (bukan EventSource) agar bisa memakai header Authorization; bus perubahan di memori satu proses acara-svc (cukup untuk satu instance).
- Status pintu: Online bila heartbeat < 45 dtk, Idle bila online tanpa scan 5 menit (atau belum pernah scan), Offline selainnya; dihitung di server (`statusPintu`).
- QR kartu dibuat di browser dengan `qrcode` (murni JS); kartu dicetak di jendela baru.
- Saat daftar wajah, tiap frame hanya dicari wajah + landmark; embedding dihitung untuk 5 frame yang diambil saja (frame dibekukan ke canvas agar pose, embedding, dan thumbnail dari gambar yang sama). Pose dinilai dari gambar kamera asli (bukan cermin), jadi sama untuk kamera depan, belakang, dan webcam.
- Wajah yang didaftarkan di perangkat memakai `clientId` sebagai id sampai terkirim; server menerima `faceDataId` berupa id atau `clientId`. Wajah dikirim lebih dulu dari antrean absensi. Salinan lokal dihapus setelah paket berikutnya (yang dibuat sesudah terkirim) diunduh.
- Verifikasi wajah oleh ADMIN di wilayah kelompok anggota itu; AUDITOR hanya melihat. "Ganti anggota" memindahkan wajah ke anggota yang benar sekaligus menyetujuinya, dan absensi yang memakai wajah itu ditandai perlu ditinjau.
- Wajah ditolak tetap ada barisnya (status, alasan, siapa) untuk jejak, tetapi embedding dan file thumbnail dihapus permanen.
- Badge verifikasi memakai SSE `GET /face/pending/stream` (bus di memori, kirim ulang paling lambat tiap 15 dtk); hook `useSse` dipakai bersama monitor pintu.
- Body JSON acara-svc dibatasi 2 MB (pendaftaran wajah membawa 5 thumbnail base64).
- Rekap sesi terbuka dihitung langsung (label "Sementara"); setelah ditutup dibaca dari tabel `Rekap` (label "Final"). Absensi pintu yang terkirim belakangan, absen susulan, dan izin yang diputuskan setelah tutup tetap menghitung ulang rekap otomatis, karena pintu offline bisa menyusul lama.
- Absen susulan memakai jam mulai sesi bila waktu tidak diisi (tidak terlambat) dan ditandai "Dicatat admin".
- PDF memakai cetak browser (gaya `print:`), bukan pustaka PDF di server, agar tanpa dependensi berat; Excel memakai exceljs (sudah dipakai core).
- Tutup otomatis memakai `setInterval` 5 menit di acara-svc (cukup untuk satu instance; perlu kunci bila diskalakan).
- Konsumen event `izin.*` dan salinan `IzinRef` ditambahkan sekarang agar rekap siap sebelum wabot (fase 7) menerbitkan izin.
- wabot menyimpan nomor di `AnggotaRef` (noWa + waliNoWa[]) alih-alih `KontakRef` terpisah: satu baris per anggota cukup untuk mencari anggota maupun anak-anak wali, dan mudah di-resync.
- Izin diajukan per sesi (bukan seluruh acara); batas waktu = `Sesi.batasIzin`, default jam mulai sesi.
- Penerima pengajuan: PJ_IZIN acara; bila tidak ada, pengurus terdekat kelompok anggota (kelompok → desa → daerah). Lewat WA hanya penerima itu yang bisa memutuskan; lewat web juga admin/pengurus yang mengelola kelompok anggota. AUDITOR hanya melihat.
- Pesan keluar dikirim satu per satu dengan jeda `WA_JEDA_KIRIM_MS` (1,5 dtk) untuk semua nomor, lebih ketat dari 1 pesan/dtk per nomor. Nomor asing dibalas sekali per 10 menit.
- Baileys (hanya ESM) dimuat dengan `import()` dinamis dari service CommonJS dan hanya bila `WA_DRIVER=baileys`.
- Halaman pengurus memakai dasbor `/admin` yang sama (menu disaring per peran), jadi `/pengurus/izin` diarahkan ke `/admin/izin`.
- Login tunggal SiKU memakai pertukaran token (core → token sekali pakai → sesi SiKU sendiri), bukan SiKU menerima access token core di setiap request: SiKU tetap memakai cookie, refresh token, CSRF, 2FA, dan izin per daerah miliknya tanpa perubahan schema, dan bisa dimatikan dengan satu flag.
- Peran SiKU disimpan di core sebagai `sikuRoles` (hanya untuk menampilkan menu); SiKU tetap sumber kebenaran peran & izin. User SiKU yang baru di core dibuat sebagai AUDITOR tanpa wilayah agar tidak melihat data acara sampai admin memberi wilayah.
